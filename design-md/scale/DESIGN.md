Overview

Scale 2.0 is a high-trust, evidence-first visual system for an AI company operating in enterprise, government, research, healthcare, defense, infrastructure, and other high-stakes domains. The system intentionally avoids the visual clichés of AI marketing. It does not rely on neon gradients, glowing networks, cyberpunk dashboards, abstract particles, or speculative “future” imagery.

The core brand idea is reliable AI for critical decisions. Every design decision should reinforce reliability, operational reality, and human accountability.

The visual system is built on four principles:

Black and white do most of the work.

Typography creates hierarchy through scale and tracking, not heavy weight.

Brand colors are restrained signals, not decoration.

Imagery must show real systems, real people, and real consequences.

The official Scale 2.0 brand system describes itself as “editorial weight, system rhythm” in typography, “neutral by default, signal when it matters” in color, and “real systems in motion” in imagery.

Core Visual Signature

The visual signature is:

large regular-weight grotesk type + black/white structure + one restrained nature-derived color + editorial photography + mono technical labels + proof-heavy content.

A correct Scale page should look believable in an annual report, an aerospace control program, a research institution, and a modern AI product company at the same time.

Colors

Philosophy

Scale’s palette is officially described as neutral by default. Black and white are the primary working colors. Earth-toned brand colors exist to create controlled signals and large editorial surfaces.

The most important rule is:

Do not use color merely because the layout feels empty.

Whitespace, typography, photography, data, and composition provide visual interest. Color should have a reason.

Color Rules

Do

Let black and white carry most pages.

Use a single brand color as a section background when color is needed.

Set text on a brand-color field in black or white only.

Use multiple brand colors only in tiny doses such as diagram nodes or icon chips.

Use alpha/opacity variations of one or two colors in charts.

Let photography provide most incidental color variation.

Don’t

Never put one brand color on top of another.

Never set colored headline text on a colored surface.

Never color individual words in a headline for emphasis.

Never build rainbow or multi-gradient section backgrounds.

Never use multiple full-strength brand colors across a single viewport.

Never introduce electric cyan, magenta, neon lime, or generic “AI purple” as unofficial accents.

Preferred Surface Rhythm

A typical page should move through surfaces like:

white → white → black → white → one brand color → white → black footer

Do not alternate colors just to create novelty. Large color fields should correspond to meaningful section transitions.

Typography

Font Family

The official primary typeface is Aeonik.

Use:

Aeonik Regular for display, headings, body, navigation, and buttons.

Aeonik Mono for literal or machine-readable detail.

The brand intentionally avoids relying on multiple type families. One grotesk carries the system.

Critical Aeonik Setting

Aeonik must use the straight-tailed lowercase “a”, enabled with the ss02 stylistic set.

Use:

font-feature-settings: "ss02" 1;

Do not use Aeonik’s default curly-tailed “a” or the single-storey alternate.

Approved Substitutes

If Aeonik is unavailable:

Use Host Grotesk for regular display/body typography.

Use Geist Mono for technical detail.

Use Noto Kufi Arabic for Arabic localization.

Do not casually substitute Inter, Space Grotesk, Helvetica Neue, or geometric tech-display faces if Host Grotesk is available.

Typography Principles

Weight

Nearly everything is Regular / 400.

Hierarchy comes from:

composition

tracking

Headline Leading

Headline leading should be tight, approximately 100% of font size.

Large Scale headlines should appear as cohesive typographic shapes.

Body Leading

Digital body text should sit around 150% line height.

For a 20px body size, use approximately 30px line height.

AI Agent Implementation Rules

The following rules are intended for autonomous or semi-autonomous design/coding agents using this file.

Priority Order

When instructions conflict, use this priority:

Brand correctness

Content clarity

Accessibility

Operational credibility

Responsive behavior

Visual novelty

Never sacrifice the first five for novelty.

Token Usage

Agents should reference token names instead of inventing values.

Correct:

color: var(--color-black);
background: var(--color-evergreen-core);

Incorrect:

color: #111827;
background: #6D5DFB;

If a value is not represented in this file, choose the closest existing token before creating a new one.

Color Decision Algorithm

When selecting a section treatment:

Default to white.

Use black if a high-contrast narrative shift is useful.

Use exactly one brand color if the section benefits from a branded editorial moment.

Keep all content on a brand-color field black or white.

Return to white or black before using a different brand color.

Do not create color mosaics.

Typography Decision Algorithm

Use Aeonik/Host Grotesk.

Use Regular 400.

Increase size before increasing weight.

Tighten tracking for larger headlines.

Use Aeonik Mono only when content is literal, indexed, numeric, or technical.

Image Selection Algorithm

Choose imagery only if it answers at least one of these:

Where is the AI being used?

Who is accountable for the outcome?

What real system is operating?

What real consequence is being managed?

Reject an image if it is merely “technology-looking.”

Component Selection Algorithm

For a new section, ask:

Is this a claim? → use large typography.

Is this proof? → use a metric, benchmark, certification, or evidence card.

Is this a real deployment? → use photography / story card.

Is this a product feature? → use a real product screenshot.

Is this research? → use tables, data visualizations, paper metadata.

Is this conversion? → use one strong CTA.

Do not solve every content type with cards.

Copy Generation Rules

Agents writing Scale-like copy should:

lead with a direct declarative sentence

describe real system behavior

mention human responsibility when relevant

use outcome verbs

substantiate claims with data when supplied

Agents must not invent customer statistics, benchmark wins, certifications, or security claims.

Source Fidelity

If working from provided Scale source material:

preserve exact product names

preserve official certification names

preserve provided metrics

do not infer security claims from visual design

label estimates as estimates

Iteration Guide

Start by identifying whether the section is claim, proof, deployment, research, product, or conversion.

Use the fewest visual ingredients necessary.

Keep black/white dominant.

Add only one brand color when a clear section-level reason exists.

Use actual operational evidence before illustrations.

Use larger regular-weight type before bold weight.

Keep mono text factual and technical.

Verify the Aeonik straight-tailed “a” when Aeonik is used.

Check every photo for real context, real work, and plausible expertise.

Check each page for overuse of cards, color, and decorative effects.

Check CTA hierarchy: one primary action per major section.

Preserve spacious editorial rhythm.

Known Gaps

Exact production CSS spacing values, breakpoints, and button measurements on scale.com are not fully documented in the public brand guide; spacing values in this file are implementation guidance inferred from the live system rather than official Scale tokens.

Aeonik is a licensed typeface. Agents without access should use the official documented fallback, Host Grotesk, rather than attempting to distribute or embed unlicensed font files.

The public brand site documents brand-level typography, color, logo, and imagery more explicitly than component-level website behavior. Component tokens in this file therefore combine official brand constraints with observed website patterns.

Motion timings and easing curves are not formally documented here.

Internal Scale product UI may use component and color systems that differ from the corporate marketing brand and should not be reverse-engineered from this file alone.

Customer logos and partner marks require correct source assets and may have separate co-branding constraints.

Partner lockups require optical review; the brand guide specifies a divider and e-based spacing, but automated agents should not assume every partner logo can be mechanically aligned without visual QA.
